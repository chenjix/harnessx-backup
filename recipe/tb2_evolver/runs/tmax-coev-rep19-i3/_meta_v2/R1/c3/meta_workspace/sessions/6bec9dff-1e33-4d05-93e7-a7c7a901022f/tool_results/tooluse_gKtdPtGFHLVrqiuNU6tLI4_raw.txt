3	"""StepBudgetVerifyProcessor — force convergence before the step budget runs out.
4	
5	Closes a systemic ``budget_exceeded`` failure mode observed on Tmax/TB2: an
6	agent burns its entire step budget on an unresolved sub-problem (a hanging
7	interactive automation, a flaky build, a stubborn service) and hits the hard
8	step cap (``exit_reason=budget_exceeded``) *never having confirmed the required
9	deliverables exist at their exact paths*. In the assigned trajectory the model
10	even renamed the one file the task explicitly required to exist to work around
11	an import error, then spent the remaining steps fighting a hanging command —
12	so at step 80 the required output path did not exist at all and the verifier
13	hard-failed on a missing file.
14	
15	The pipeline already carries two convergence mechanisms, but neither fires in
16	this situation:
17	
18	* ``CustomSelfVerifyProcessor`` injects an excellent pre-exit verification
19	  checklist, but only when the model *voluntarily tries to stop* (an
20	  exit-intent turn). A run that dies at the step cap never produces an
21	  exit-intent turn, so the checklist is never shown.
22	* ``TaskTimeReminderProcessor`` warns at time fractions, but it is a no-op
23	  unless ``timeout_seconds`` is supplied (it is not in the live config), and
24	  even when active its text is a generic "time is running low" nudge, not a
25	  concrete "confirm each required output file exists now" checklist.
26	
27	This processor closes the gap by counting steps itself (the run loop does not
28	expose a step index on the event, so we track it locally, exactly as
29	``TaskTimeReminderProcessor`` tracks elapsed time) and, once the run crosses a
30	configurable fraction of the known step budget, injecting a single
31	budget-proximity verification message. The message tells the agent it is close
32	to the hard step cap and must, right now, (a) re-read the task requirements,
33	(b) confirm every required output artifact exists at its exact stated path and
34	is non-empty, and (c) stop fighting any single stuck sub-problem and instead
35	produce the best-possible required deliverables while budget remains.
36	
37	Generalisation: entirely task-agnostic. It names no task, path, command, or
38	constant, keys only on the step budget fraction, and fires at most once per
39	run. It benefits any task at risk of ``budget_exceeded`` — steering the model
40	to salvage the required outputs before the cap instead of discovering at the
41	last step that nothing was produced.
42	"""
43	
44	from __future__ import annotations
45	
46	import dataclasses
47	
48	from harnessx.core.events import (
49	    Message,
50	    StepStartEvent,
51	    TaskEndEvent,
52	    TaskStartEvent,
53	)
54	from harnessx.core.processor import MultiHookProcessor
55	
56	_BUDGET_MSG = (
57	    "[StepBudget] You are approaching the hard step limit for this task "
58	    "(~{used}/{budget} steps used). You may not get many more turns, and the "
59	    "run will be terminated when the cap is hit — leaving whatever state the "
60	    "workspace is in right now. Stop fighting any single stuck sub-problem and "
61	    "converge on the deliverables. Do this now, before continuing:\n"
62	    "1. Re-read the task requirements and list every artifact the task "
63	    "explicitly requires (exact file paths, running services, log contents).\n"
64	    "2. For each required file, run `ls -lh <exact_path>` and `head`/`cat` it "
65	    "to confirm it EXISTS at the exact required path and holds the correct "
66	    "content. A workaround that renamed, moved, or skipped a required output "
67	    "means that requirement is currently UNMET — restore it.\n"
68	    "3. If a sub-step is still failing, prefer a simpler approach that still "
69	    "satisfies the stated requirement over continuing to retry the failing "
70	    "one; a partially-correct deliverable at the right path beats an empty or "
71	    "missing one.\n"
72	    "4. Verify running services are still alive right now, not just that they "
73	    "started earlier.\n"
74	    "Prioritise producing every required output at its exact path with the "
75	    "remaining budget."
76	)
77	
78	
79	class StepBudgetVerifyProcessor(MultiHookProcessor):
80	    """Inject a one-shot verification checklist as the step budget nears its cap.
81	
82	    Parameters
83	    ----------
84	    step_budget:
85	        The hard step cap for a task run (Tmax/TB2 default is 80). Used only to
86	        compute the warning threshold; if the real cap differs the nudge simply
87	        fires at a slightly different absolute step.
88	    warn_fraction:
89	        Fraction of ``step_budget`` at which the one-shot nudge fires
90	        (default 0.8 → step 64 of 80). Chosen to leave a meaningful tail of
91	        turns for the agent to act on the checklist before the cap.
92	    """
93	
94	    _singleton_group = "step_budget_verify"
95	    _order = 7  # after TaskTimeReminderProcessor (6); a step_start context nudge
96	
97	    def __init__(
98	        self,
99	        step_budget: int = 80,
100	        warn_fraction: float = 0.8,
101	    ) -> None:
102	        self.step_budget = max(1, int(step_budget))
103	        self.warn_fraction = min(max(float(warn_fraction), 0.0), 1.0)
104	        self._threshold = max(1, int(self.step_budget * self.warn_fraction))
105	        self._steps = 0
106	        self._fired = False
107	
108	    async def on_task_start(self, event: TaskStartEvent):
109	        self._steps = 0
110	        self._fired = False
111	        yield event
112	
113	    async def on_step_start(self, event: StepStartEvent):
114	        self._steps += 1
115	        if self._fired or self._steps < self._threshold:
116	            yield event
117	            return
118	        self._fired = True
119	        msg = Message(
120	            role="user",
121	            content=_BUDGET_MSG.format(used=self._steps, budget=self.step_budget),
122	        )
123	        yield dataclasses.replace(
124	            event,
125	            messages=event.messages + (msg,),
126	            raw_messages=event.raw_messages + (msg,),
127	        )
128	
129	    async def on_task_end(self, event: TaskEndEvent):
130	        self._steps = 0
131	        self._fired = False
132	        yield event
