Reading text from images (OCR): a first raw OCR pass is often wrong, and
committing a garbled read as a literal value silently fails downstream
checks. Treat OCR output as untrusted until verified:
- Watch for quality warnings from the OCR engine (e.g. an "Invalid
  resolution"/low-DPI notice, or an estimated resolution that differs from
  the one actually used). These almost always mean the raw read is garbled.
- When the read looks noisy, re-run after improving the input: upscale the
  image several times and set an explicit high DPI (around 300) so the
  engine has enough resolution; grayscale/threshold/contrast preprocessing
  can help further. Try more than one page-segmentation mode.
- Sanity-check the extracted text against what it must be: keys, tokens,
  and structured strings have known shapes (fixed prefixes, character sets,
  length). If characters look implausible (letter/digit confusions like
  l/1/I or O/0, stray punctuation, spaces inside a token), the read is
  corrupt — fix the OCR rather than guessing or hand-patching the string.
- Never fabricate or "infer" the exact value from context when an accurate
  read is required; keep improving the OCR until the output is clean and
  self-consistent.
