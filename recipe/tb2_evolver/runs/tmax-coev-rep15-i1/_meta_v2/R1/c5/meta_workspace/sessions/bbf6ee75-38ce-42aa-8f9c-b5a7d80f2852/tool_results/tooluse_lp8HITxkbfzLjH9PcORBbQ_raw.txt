20	### Why
21	
22	`task_000118_3043e92d` failed `budget_exceeded` at 80 steps / 924s.
23	The agent entered a degenerate repetition loop: it emitted the same
24	long reasoning block ("The user is right - I've been stuck in a loop...
25	In the earlier test: - Second 1: Disk size 4096 bytes...") verbatim on
26	~10+ consecutive turns, each cut off by the token limit and re-primed by
27	a passive "please continue" nudge. The existing
28	`LengthTruncationRecoveryProcessor` fired but its soft escalating nudge
29	was ignored on every turn — the model's own stale narration in the
30	context window outweighed a one-line user message, and several looping
31	turns did not even carry `finish_reason=length` so the length processor
32	never triggered on them. The agent *could* act correctly when it briefly
33	broke out (it ran real Bash commands and observed the 200MB log dir at
34	line 218) but immediately fell back into the loop and never recovered.
35	This is a mechanical context pathology, not a missing capability.
36	
37	### Changes
38	
39	- `processors/repetition_loop_breaker.py` — new `RepetitionLoopBreaker`
40	  `MultiHookProcessor`. Fingerprints normalised prefixes of consecutive
41	  tool-less assistant turns; on ≥3 near-identical repeats it prunes the
42	  poisoned duplicate assistant messages (and passive continue nudges)
43	  from context and injects one decisive "one Bash command only" redirect.
44	  Content-agnostic — names no task, path, or constant.
45	- `config.yaml` — register `RepetitionLoopBreaker` (order 6, after
46	  length-recovery, before compaction); lower
47	  `LengthTruncationRecoveryProcessor.head_chars` 1200→700 so collapsed
48	  runaway narration re-primes the next completion less strongly.

61	### Uncertainty
62	
63	Risk is a false positive on genuine repeated reasoning. Guarded by
64	requiring ≥3 consecutive tool-less turns with an identical 400-char
65	normalised prefix, each ≥200 chars, and a full reset the moment any
66	tool call fires. Worst case on a false positive is one extra redirect
67	message and a slightly trimmed context — benign. If the breaker fires
68	on a previously-passing task and regresses it, the rollback trigger
69	above applies.
