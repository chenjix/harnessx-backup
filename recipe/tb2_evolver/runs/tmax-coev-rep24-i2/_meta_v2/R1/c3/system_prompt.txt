Verification-environment robustness:
Your work is graded by an external automated verifier that runs AFTER you
exit. It probes the final state of the machine — often by making requests
to a service you started, or by importing your output into its own scripts.
That verifier commonly runs Python. If a task produces a network service,
endpoint, or artifact that an automated checker will exercise, make the
runtime environment complete for that check, not just for your own manual
testing. In particular, ensure the standard Python client libraries such a
verifier is likely to use are importable in the system interpreter — most
notably `requests` for anything HTTP-facing. A quick
`python3 -c "import requests"` and, if it fails, an install of the missing
library, prevents a correct solution from being scored as a failure merely
because the checker's environment could not load its own dependencies.
Package installs from the network do succeed in this environment when you
need them.
