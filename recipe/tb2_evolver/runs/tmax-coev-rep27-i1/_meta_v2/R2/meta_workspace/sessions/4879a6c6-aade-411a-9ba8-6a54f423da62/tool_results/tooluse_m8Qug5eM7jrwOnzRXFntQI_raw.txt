20	### Why
21	
22	R0 scored 41/50 (0.82). Of the 9 failures, only one root cause recurred
23	across ≥2 distinct tasks with the same mechanism: the verifier's test module
24	does `import requests` at collection time, and the agent — which never sees
25	the verifier file — never installs `requests`. Both affected tasks build a
26	localhost network service (task_000028: Nginx + C++ backend on :8080;
27	task_000958: C++ HTTP microservice on :9090), test them with `curl`/`ss`, and
28	exit reporting success. The verifier then dies with
29	`ModuleNotFoundError: No module named 'requests'`, scoring 0 regardless of
30	whether the service is correct. For task_000958 this was a hard collection
31	error blocking ALL assertions. The other 7 failures are one-off,
32	distinct-mechanism capability/logic gaps (process cleanup, log-rotation size,
33	SQLite index usage, numeric error, packaging, text-casing) plus a task-design
34	collision (task_000010's mandated `operator.py` shadows the stdlib module and
35	breaks the verifier's Python) — none harness-fixable without embedding domain
36	knowledge, so logged as skips.
