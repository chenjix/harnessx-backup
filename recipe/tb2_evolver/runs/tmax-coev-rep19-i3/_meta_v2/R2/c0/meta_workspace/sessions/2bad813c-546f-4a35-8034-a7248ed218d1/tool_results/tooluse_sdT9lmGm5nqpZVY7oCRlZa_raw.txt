20	### Why
21	
22	Assigned focus `task_000028_7fe033ac` (nginx reverse-proxy → C++ UNIX-socket
23	backend) died `budget_exceeded` at 80 steps / 544s, reward 0, verifier
24	502 Bad Gateway. The trajectory tail shows the agent running a
25	byte-identical Bash command (`pkill -9 server ...; /app/server ...;
26	python3 -c "import socket..."`) 12 times in a row. Each run SUCCEEDED
27	(backend returned `HTTP/1.1 200 OK ... 150`) — the real fault was
28	elsewhere (nginx couldn't reach the socket) — yet the agent kept
29	re-probing the part that already worked. The existing
30	`RepeatedCommandBreaker` fired its `_HARD` advisory each turn
31	("Your very next command MUST be different") and the model ignored it
32	every single time. The same shape recurs on two more R0 failures:
33	task_000118 re-issued `ps aux | grep -v grep | grep python` 16 times,
34	task_000506 re-issued a `wfg_analyzer.py` probe 21 times — both
35	`budget_exceeded`, reward 0. The harness deficiency: the loop breaker
36	was advisory-only and had no teeth against a weaker model.
37	
38	### Changes
39	
40	- `processors/repeated_command_breaker.py` — new copy of the processor
41	  adding an `on_before_tool` HARD BLOCK: once a byte-identical command
42	  has already executed `block_threshold` times, the next re-issue is
43	  short-circuited (`approved=False` + `synthetic_result`), not executed.
44	  Existing warn(3)/hard(5) advisories retained.
45	- `config.yaml` — repoint `RepeatedCommandBreaker` `_target_` to the new
46	  file and add `block_threshold: 7`.
47

61	### Uncertainty

64	fix (e.g. the nginx socket-path/permission bug on task_000028). If the
65	cluster stays red at `budget_exceeded` even with steps freed, the gap is
66	a capability/knowledge one (debugging reverse-proxy integration), not a
