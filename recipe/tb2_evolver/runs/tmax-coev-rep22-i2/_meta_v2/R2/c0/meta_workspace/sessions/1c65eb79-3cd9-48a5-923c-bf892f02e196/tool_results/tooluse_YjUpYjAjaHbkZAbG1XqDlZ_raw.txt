161	### Why
162	
163	Assigned focus `task_000028_7fe033ac` did NOT fail inside the agent loop. Its
164	`result.json`: `status=error`, `elapsed_s=0.1`, no `messages.json` — the
165	container never started. Error:
166	`docker run failed ... Conflict. The container name
167	"/tmax-task0000287fe033ac-1788232928" is already in use`.
168	
169	This is systemic, not a one-off: 26 of 137 task result rows (~19%) errored with
170	the identical container-name conflict, all `elapsed_s~=0.1`, all trajectory-less
171	(includes R1 targets task_000010/task_001090 and R2 OCR targets
172	task_000015/task_000505 — prior interventions could not even be evaluated this
173	round). Root cause is in `recipe/tmax_eval/docker_env.py::start_container`:
174	`name = f"tmax-{task_id.replace('_','')[:20]}-{int(time.time())}"` collides on
175	same-second retries / un-reaped stale containers, and there is no `docker rm -f`
176	+ retry. `run_eval.run_one` calls `start_container()` BEFORE
177	`harness_runner.run_harness_agent()`, so no processor/tool/system-prompt hook in
178	the meta-agent's write scope fires before `docker run`. The failure is
179	structurally unreachable by `HarnessConfig`.
