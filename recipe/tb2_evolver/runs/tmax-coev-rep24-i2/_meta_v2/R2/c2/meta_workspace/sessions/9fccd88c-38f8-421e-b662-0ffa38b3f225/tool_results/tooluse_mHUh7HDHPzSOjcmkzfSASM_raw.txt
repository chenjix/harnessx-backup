20	### Why
21	
22	Assigned focus `task_000106_23215092`: the agent built a fully correct
23	Flask co-authorship API (correct SQL, PageRank, exact JSON shape, 404
24	handling — all verified via `urllib` in-trajectory) yet scored 0. The
25	verifier's `test_final_state.py` does `import requests`, which is absent
26	from the image, so pytest errors at *collection* and the correct service is
27	never exercised. TB2 injects verifier tests after the agent exits, so the
28	agent has no signal the grader needs `requests`; it (and every agent in this
29	cluster) probes with `urllib`/`curl`, which are preinstalled. This same
30	`ModuleNotFoundError: No module named 'requests'` at collection appears on 7
31	of 31 failing tasks — all HTTP-service tasks. It is a harness deficiency,
32	not a capability gap: pip works during the agent phase (numpy/scipy were
33	installed successfully in the same trajectory).

35	### Changes
36	
37	- `processors/grader_client_deps.py` — new `GraderClientDepProcessor`
38	  (`MultiHookProcessor`). Arms when a Bash command matches a generic
39	  HTTP-service signature (flask/fastapi/uvicorn/http.server/port binds/
40	  `127.0.0.1:<port>`/`--port`/…); on exit-intent (`on_after_model`, no tool
41	  calls) injects one idempotent, offline-safe `pip install requests` Bash
42	  call. Fires at most once per task. No task ids or dataset literals.
43	- `config.yaml` — register the processor (absolute `file://` path) at
44	  `_order=88`, immediately before `CustomSelfVerifyProcessor`.
45	- `system_prompt.txt` — copied byte-identical to R0 default (sibling builder
46	  requirement); no prompt change.
