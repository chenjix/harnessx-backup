20	### Why
21	
22	Assigned focus task_000106_23215092 built a correct Flask API on
23	127.0.0.1:8000, started it, and verified all endpoints with `urllib` — yet
24	scored reward=0. The failure is entirely in the verifier phase: the injected
25	`test_final_state.py` begins with `import requests`, the base image lacks
26	`requests`, so pytest aborts at *collection* (`Interrupted: 1 error during
27	collection`) and every test errors at once regardless of solution correctness.
28	The agent had no way to anticipate this — the test file does not exist during
29	the agent phase, and testing with `urllib`/`curl` is entirely valid. A grep
30	over all `*.result.json` shows the identical `No module named 'requests'`
31	collection abort on exactly 5 tasks — task_000106, task_000028, task_000958,
32	task_001857, task_002063 — every one an HTTP server / microservice task, none
33	of which used or installed `requests`. This is a harness deficiency, not a
34	model capability gap.
35	
36	### Changes
37	
38	- `processors/verifier_dep_ensurer.py` — new `VerifierDepEnsurer`
39	  `MultiHookProcessor`. `on_task_start` arms only tasks whose description names
40	  an HTTP/REST server AND a concrete endpoint/port/listen surface. On the first
41	  approved Bash call of an armed task, prefixes the command with an idempotent,
42	  silent, best-effort guard:
43	  `python3 -c 'import requests' 2>/dev/null || pip install -q requests >/dev/null 2>&1 || true ; <original>`.
44	  Fires at most once per task; never mutates message history.
45	- `config.yaml` — register `VerifierDepEnsurer` via absolute `file://` path,
46	  placed after the time-reminder and before length-recovery (its `_order=10`
47	  makes it run early among before-tool processors).

65	### Uncertainty
66	
67	Two ways to tell if the bet is wrong next round: (1) if the 5 predicted tasks
68	don't flip, either the agents' solutions were also wrong (task collection now
69	runs but assertions fail) — in which case the guard did its job and the
70	remaining gap is a model capability issue to log separately; or (2) if an
71	offline image makes the pip install fail — the guard is `|| true`, so the task
72	is exactly as it is today (no new failure). Regression on a previously-passing
73	HTTP-service task attributable to the guard is the rollback trigger.
