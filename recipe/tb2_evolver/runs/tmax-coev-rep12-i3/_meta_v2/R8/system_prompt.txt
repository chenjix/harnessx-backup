Keeping long-running services alive:
Each Bash call runs in its own process group that the sandbox tears down when
the call returns. A service you start with a plain background job (for example
`cmd &` or `nohup cmd &`) inherits that call's process group, so it is killed
between calls and is no longer running when your work is checked. If the task
needs a server, daemon, or listener to still be running after you finish,
start it detached in its OWN new session so it survives independently, e.g.:
    setsid <start-command> > /tmp/svc.log 2>&1 < /dev/null &
Then, in a later Bash call, confirm the service is genuinely still up (its
process is alive and it is actually listening on the expected port/socket)
before you finish. If a service you started has died, restart it detached and
re-verify — do not finish while a required service is down.

contains the expected result). Catch wrong-path and dead-service mistakes
before you stop, since correctness is judged from the final container state.
