3	## Candidate C-002 — content-repetition (narration loop) recovery processor
4	
5	- **Lens / Lever / Intent**: control-loop failure detection / **control** (new
6	  `MultiHookProcessor`) / close a systemic thrash cluster + cut wasted cost.
7	- **Signal (frontmatter sweep)**: 4 of the 5 `budget_exceeded`/`max_steps`
8	  failures (all pinned at the 80-step cap) show degenerate narration loops.
9	- **Verified body evidence** (from `_meta_scratch/probe5.py` over the R1
10	  trajectory messages.json):
11	  - `task_000910_16cc0daf`: **15 consecutive identical** assistant turns
12	    ("Let me try a different approach - use a simpler command to compile and
13	    test."). exit=budget_exceeded, 80 steps.
14	  - `task_001028_5bc8bc70`: **9 consecutive identical** turns ("I've been stuck
15	    in a loop trying to understand the binary. Let me take a completely
16	    different approach.") — 24 turns share the same 60-char prefix.
17	    exit=budget_exceeded, 80 steps.
18	  - `task_000716_206dc0f6`: 4 consecutive identical turns; multiple prefix
19	    clusters incl. env-injected "stop the repetition" already present but not
20	    breaking the loop. exit=budget_exceeded, 80 steps.
21	  - `task_001877_bd2513aa`: repeated OCR-extraction narration; exit=budget_exceeded.
22	- **Why this is harness-shaped, not capability**: the *loop* is the harness
23	  deficiency (no mechanism catches a normal-finish narration loop), even though
24	  the underlying task is hard. Existing guards miss it:
25	  - `LengthTruncationRecoveryProcessor` only fires on `finish_reason=="length"
26	    and not tool_calls`; these turns finish normally / carry tool calls.
27	  - `CustomEditToolProcessor` only counts repeated *file-write* commands
28	    (redirects/sed -i/tee); these are diagnostic/compile commands.
29	  - `CustomSelfVerifyProcessor` fires once, only on exit-intent.
30	- **Change**: new `processors/content_repetition_recovery.py::
31	  ContentRepetitionRecoveryProcessor`, `_order=6` (right after length-recovery).
32	  Fingerprints normalized assistant content; after `repeat_threshold=3`
33	  consecutive look-alike turns injects a corrective nudge (change tactic /
34	  gather new evidence), escalating at `escalate_threshold=5` to a hard
35	  "STOP — write the required output file to its exact path or run one genuinely
36	  new command". +1 user message per chain max (replaces a trailing user msg if
37	  present) — contract-safe. `min_content_chars=40` avoids tripping on terse
38	  action turns.
39	- **Retroactive check (counterfactual)**: had this processor been live in R1,
40	  task_000910 would have been interrupted after turn 3 of its 15-turn identical
41	  streak (~step 6-9 instead of 80) and task_001028 after turn 3 of its 9-turn
42	  streak. Neither is guaranteed to flip (both are genuinely hard: multi-service
43	  daemon + binary RE), but the escalated nudge routes the model toward writing
44	  the required output file before the step cap — the specific gap that scored
45	  them 0 (files never created). Worst realistic case: no flips but large step/
46	  cost savings on the loop cluster.
47	- **Why control (new processor) not instruction (system prompt)**: the system
48	  prompt already tells the agent to plan and not repeat; the loops happen
49	  *anyway* mid-run. A static prompt cannot detect a live repetition streak — a
50	  processor watching `on_after_model` can. This is a detection/interception gap,
51	  the canonical case for a `MultiHookProcessor`.
52	- **expected_global_gain**: primary win is cost/step reduction across the
53	  ~4-task loop cluster (each currently burns the full 80-step cap on repeated
54	  output); secondary chance to flip a borderline task by forcing an earlier
55	  pivot to writing required outputs. Generalizes to any future narration-loop
56	  task, not just these four.
57	- **regression_risk**: a nudge could fire on a *legitimately* iterative task
58	  that happens to narrate similarly. Mitigated by (a) high threshold (3 near-
59	  identical turns, escalate at 5), (b) `min_content_chars` floor, (c) the nudge
60	  is advisory text, never blocks or drops a tool call, (d) counter resets after
61	  each nudge so it fires at most once per streak-start. No already-passing task
62	  in R1 showed a 3+ identical-narration streak (passing tasks finished in
63	  6-33 steps), so predicted collateral on the passing set is near zero.
64	- **cost_shift**: net **negative** (cheaper). Interrupting a 15-turn identical
65	  streak at turn 3 removes ~12 wasted model turns on affected tasks; the nudge
66	  itself is one short user message. On non-looping tasks the processor is a pure
67	  no-op (no message added).
68	- **rollback_trigger**: if R3 pass_rate drops below R1 (20/50) beyond repeat
69	  noise, OR the synthetic replay / any task shows `exit_reason=error`
70	  attributable to this processor, OR a previously-passing task regresses with a
71	  content-repetition nudge visible in its transcript → revert to R1 config.
