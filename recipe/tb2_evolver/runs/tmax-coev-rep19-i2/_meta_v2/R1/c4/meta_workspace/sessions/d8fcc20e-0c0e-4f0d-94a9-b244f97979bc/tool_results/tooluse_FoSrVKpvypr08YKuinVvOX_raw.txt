20	### Why
21	
22	Assigned focus was `task_000028_7fe033ac` (system_administration, reward=0).
23	Reading its trajectory: the agent fully solved the task — fixed the nginx
24	`proxy_pass`, rewrote the C++ socket server to compute the frame count via
25	ffprobe, compiled it, ran it in the background, wrote the logrotate config,
26	chmod'd the socket to fix a 502, and verified `HTTP/1.1 200 OK` with body
27	`150` through nginx on `127.0.0.1:8080`. It still scored 0. The cause is
28	entirely in the verifier phase: `final_pytest` errors with
29	`ModuleNotFoundError: No module named 'requests'` while *collecting*
30	`/tmp/test_final_state.py` — the verifier can't even load its own test
31	module because the base image lacks `requests`.
32	
33	A sweep of the round's 27 failures found this is a **6-task cluster** (000028,
34	000106, 000809, 000958, 001857, 002063) — every one a build-a-service task
35	whose external verifier probes over HTTP with Python `requests`, all failing
36	with the identical import-collection error. This is a harness deficiency, not
37	a model capability gap: the agent can't see the verifier's test files during
38	its phase (sandbox topology, per tb2-playbook), so it has no way to know
39	`requests` is needed; and it tests its own service with curl/`/dev/tcp`, so it
40	has no local signal to install it. Critically, task_000106 proves outbound pip
41	works here (`pip3 install numpy`/`scipy` both succeed from PyPI) — so the fix
42	is available, the agent just lacks the knowledge to apply it.
43	
44	### Changes
45	
46	- `processors/verifier_http_dep_reminder.py` — new `VerifierHttpDepReminder`
47	  `MultiHookProcessor`. On the first step, if the task description matches BOTH
48	  an external-verifier signal AND a build-a-service signal, appends one `user`
49	  reminder to ensure the system Python has the standard HTTP client library
50	  before finishing (agent runs the install itself via Bash). Fires at most once
51	  per task; no task-specific literals.
52	- `config.yaml` — register `VerifierHttpDepReminder` (dep_module=requests) in
53	  the pipeline at `_order=7`, just after `TaskTimeReminderProcessor`.
54	- `system_prompt.txt` — copied byte-for-byte from R0 (SiblingSystemPromptBuilder
55	  resolves it relative to the active config dir).
