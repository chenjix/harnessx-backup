87	### Why
88	
89	Assigned focus: recovery from tool errors. Sweeping R0 fails (25/50)
90	for non-zero-exit + duplicate-command co-occurrence surfaced a tight
91	cluster where the agent re-issues a command that keeps failing the
92	SAME way and never changes approach: task_001818 (12 non-zero exits,
93	32 dups, exit=error), task_001701 (11 errors, 13 dups, budget), and
94	task_001673 (7 errors, 18 dups, budget). The observable state is a
95	same-normalised-command / same-error-fingerprint repetition. R0's
96	existing guards do not cover it: CustomEditToolProcessor counts file
97	over-edits (write-count, ignores exit status) and
98	LengthTruncationRecoveryProcessor only handles finish_reason=length.
99	The anchor task_000010 is partial evidence (its "recovery" was a
100	requirement-violating file rename rather than a blind repeat), so the
101	cluster stands on the three loop tasks.
102	
103	### Changes
104	
105	- `processors/stuck_command_recovery.py` — new MultiHookProcessor
106	  StuckCommandRecoveryProcessor: tracks (normalised command, error
107	  fingerprint) across tool results; after repeat_threshold consecutive
108	  identical failures injects ONE legible loop-break note (names the
109	  repeated command + recurring error, instructs inspect-inputs /
110	  change-invocation / isolate-failing-piece), then arms a cooldown
111	  until the command signature changes. Bounded by max_nudges.
112	- `config.yaml` — register the processor (repeat_threshold=3,
113	  max_nudges=3) just before CustomEditToolProcessor.
114	- `system_prompt.txt` — copied byte-for-byte from R0 (SiblingSystemPromptBuilder).

121	  53/75 but is ignored (write-count based).
122	- task_001673 steps 25-60: verbatim cycle (start flask server &, urllib
123	  request returning {"cost":null}, sqlite recursive-CTE returning the

125	- task_001701 steps 2-45: jshon invocation on a nested JSON object

130	### Uncertainty
131

135	"step back". If R3 shows the dup-command / non-zero-exit counts on the
136	predicted tasks unchanged, the next round should escalate to a harder
137	intervention (e.g. block the identical re-execution outright).

156	### Why
157	
158	Assigned focus: complementary synthesis of the live pivots. The pivot
159	table's headline scores (c4=0.46, c1=0.38 vs R0=0.50) are misleading: most
160	reported "unique losses" are `status: error` docker container-name
161	conflicts (parallel-scheduling infra flakes), NOT harness regressions.

226	### Why
227
