20	### Why
21	
22	`task_000140_01c78b42` (system_administration) fails on
23	`test_no_lingering_service_processes`, which asserts no `vm_service`
24	processes remain after the agent exits (final pytest lists lingering PIDs
25	`['347','572','849','1061']`). The agent actually solved the task — main.go,
26	start_service.sh, and test_pipeline.sh were all correct — but it re-ran
27	`test_pipeline.sh` multiple times to verify it (the log ends with the
28	`PROVISIONED_VM_FOR: admin_alice` line written twice). Each run started a
29	fresh `./vm_service &`; the pipeline's shutdown only killed the single PID in
30	`service.pid` (the last one), orphaning the rest. The agent had no visibility
31	into the cumulative side effects of its own iterative testing — every Bash
32	call is stateless from its perspective. This is a harness deficiency
33	(runtime awareness gap), not a capability gap.
34	
35	### Changes
36	
37	- `processors/lingering_process_guard.py` — new `LingeringProcessGuard`
38	  MultiHookProcessor. Passively tracks background launches (`&`/`nohup`/
39	  `setsid`/`disown`); at exit intent, if background work was launched, reads
40	  the live `ps` table and, only when it finds >=2 instances of the same
41	  command signature (re-run orphan fingerprint), injects one informational
42	  warning listing the duplicate PIDs and asks the agent to clean up
43	  deliberately. Never kills anything. Ordered 92 (after self-verify's 90).
44	- `config.yaml` — register `LingeringProcessGuard` at the end of the
45	  processor pipeline via absolute `file://` path.
46	- `system_prompt.txt` — copied byte-for-byte from R0 (unchanged).

63	### Uncertainty
64	
65	The guard depends on the agent acting on the injected warning within its
66	remaining turn budget; a very-late exit could leave no room to `kill`. It is
67	strictly informational to avoid regressing tasks that must keep a single
68	service alive (system prompt explicitly instructs that), and it fires only on
69	duplicates, so false positives on legitimate single-service tasks are
70	unit-test-confirmed to be zero. If R2 shows a background-service task
71	flipping T->F, the ordering/keepalive interaction with self-verify is the
72	first suspect — revert.
