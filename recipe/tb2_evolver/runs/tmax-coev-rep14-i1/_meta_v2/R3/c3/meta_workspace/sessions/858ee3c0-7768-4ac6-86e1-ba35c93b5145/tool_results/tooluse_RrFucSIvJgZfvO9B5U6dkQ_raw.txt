454	### Why
455	
456	Assigned focus `task_000010_644ab1c2` (system_administration, reward=0,
457	exit_reason=done, steps=65). The task requires a script at `/home/user/operator.py`,
458	but that filename shadows Python's stdlib `operator` module — so any `python3`
459	process with `/home/user` on `sys.path[0]` triggers a circular import
460	(`from operator import eq` inside `collections`). final_pytest fails with that
461	exact circular-import traceback.
462	
463	The agent correctly *diagnosed* the shadowing but never escaped it. It fell into a
464	byte-identical 2-cycle (messages.json msgs 45–54): tool_call
465	`rm operator.py && ln -sf k8s_operator.py operator.py && python3 -c "import operator"`
466	→ `OK`, alternating with `cd /tmp && python3 k8s_operator.py` → the same traceback,
467	9× each, until the run ended with no working deliverable.
468	
469	Root harness gap: nothing in R0 intercepts a loop of *completed* tool calls whose
470	results never change. `LengthTruncationRecoveryProcessor` only handles
471	`finish_reason=="length" and not tool_calls` (no-tool-call token-cap loops) — the
472	other loop shape in this same trajectory (msgs 58–84). The completed-tool-call loop
473	was uncovered. Sweep confirmed a recurring cluster: task_000958 (sqlite3 x13,
474	budget_exceeded), task_001706 (x12, budget_exceeded), task_001031 (x47, error).
475	
476	Critically, task_000010's loop is a 2-cycle, so a naive "N consecutive identical
477	results" detector (max strictly-consecutive = 2) misses it. A rolling window of the
478	last 6 (command,result) fingerprints collapsing to <=2 distinct values catches both
479	the 2-cycle AND the back-to-back reruns. Empirically, 0 of 29 R2-passing tasks hit
480	this condition — the shape is exclusive to the looping/failing cluster.
481	
482	Distinct from reverted R1 `h_step_budget_reminder_v1` (a step-fraction reminder,
483	control): this fires on the *repetition shape* of tool results, not on a budget
484	threshold, and is append-only on the result rather than injecting user messages.
485	
486	### Changes
487	
488	- `processors/degenerate_loop_breaker.py` — new `DegenerateLoopBreakerProcessor`
489	  (`MultiHookProcessor`, `_order=33`, after CustomEditToolProcessor(30), before
490	  CustomSelfVerifyProcessor(90)). Pairs each command with its result in
491	  `on_before_tool`/`on_after_tool`, maintains a rolling window of blake2b
492	  fingerprints; when distinct fingerprints in the window <= `distinct_max` it

496	  again without spamming.
497	- `config.yaml` — register the processor via absolute `file://` path
498	  (window=6, distinct_max=2, min_window_fill=6, refire_gap=4). Rest byte-identical
