3	"""NumericCrossCheckNudge — one-shot pre-exit reminder to independently
4	re-derive a *computed numeric* deliverable before committing it.
5	
6	Motivation (Tmax/TB2 ``scientific_computing`` cluster)
7	------------------------------------------------------
8	On this round every ``scientific_computing`` task scored 0. The recurring
9	*shape* — not the recurring *bug* — is this: the agent writes a plausible
10	implementation, runs it once, obtains a specific number (a regression slope, a
11	Monte-Carlo mean, a numerical integral, an optimal grid size), verifies only
12	that the output FILE exists and is correctly *formatted*, and exits after very
13	few steps. Two assigned/adjacent trajectories terminated in 7 steps having
14	never cross-checked the *value* by any independent route:
15	
16	* ``task_000111`` — hand-rolled OLS produced slope 2.5056; the reference
17	  expected 2.5997. The code was textbook and self-consistent, so the agent had
18	  no internal signal that it was off.
19	* ``task_001330`` — Monte-Carlo line fit committed on the first run with no
20	  reconciliation of the polyfit argument order / noise-application convention
21	  against a second formulation.
22	
23	The verifier's test files are injected only *after* the agent exits (TB2
24	sandbox topology), so the agent can never read the grader. Its only defence
25	against a spec-noncompliant number is to *reconcile the value against an
26	independent second method of its own* before committing — e.g. a manual
27	normal-equations slope cross-checked with ``numpy.polyfit``; a manual Riemann /
28	trapezoid integral cross-checked with ``scipy.integrate``; a closed-form mean
29	cross-checked with the empirical one. When two independent routes disagree
30	beyond rounding, the implementation (or its reading of the spec) is wrong and
31	the agent still has budget to investigate.
32	
33	Why this is not task-specific knowledge
34	---------------------------------------
35	The nudge names no task, no dataset, no algorithm, no constant, and no file
36	path. It encodes a single general strategy — *cross-validate a required
37	computed number by a second independent method before finishing* — that
38	transfers to any task whose deliverable is a specific computed value. It is the
39	computational analogue of the existing file-existence checklist.
40	
41	Composition with the existing pipeline
42	---------------------------------------
43	``CustomSelfVerifyProcessor`` (order 90) already intercepts the first
44	exit-intent turn, converts it into a keepalive tool call, and appends a
45	file/format verification checklist on the following ``on_before_model``. This
46	processor is deliberately ordered *after* it (order 91) and keys on the *same*
47	exit-intent signal, appending its numeric-reconciliation addendum as one extra
48	user message on that same pre-model turn. It fires **at most once per task**
49	and is a no-op on the exit turn if it never sees an exit-intent, so a run that
50	dies at the step cap is unaffected. It adds no tool calls of its own, so it
51	cannot interfere with the keepalive mechanism.
52	"""
53	
54	from __future__ import annotations
55	
56	import dataclasses
57	
58	from harnessx.core.events import (
59	    BeforeModelEvent,
60	    Message,
61	    ModelResponseEvent,
62	    TaskEndEvent,
63	    TaskStartEvent,
64	)
65	from harnessx.core.processor import MultiHookProcessor
66	
67	_CROSSCHECK_MSG = (
68	    "[NumericCrossCheck] Before you finish: does this task require a specific "
69	    "COMPUTED value as its deliverable (e.g. a fitted coefficient, a mean, a "
70	    "confidence-interval bound, a numerical integral, an optimized parameter, "
71	    "a count)? If so, a file that exists and is correctly formatted is NOT "
72	    "enough — the number itself must match the intended calculation, and the "
73	    "grader is hidden from you, so a self-consistent-but-wrong implementation "
74	    "will pass all of your own checks and still fail.\n"
75	    "Do this now, once, before exiting:\n"
76	    "1. Re-derive each required numeric result by a SECOND, independent method "
77	    "and compare. Examples of independent second routes: a hand-rolled formula "
78	    "cross-checked against a library primitive (or vice-versa); a closed-form "
79	    "value against an empirical/simulated one; a different but equivalent "
80	    "algebraic formulation. If two independent routes agree to the required "
81	    "precision, trust the value; if they disagree beyond rounding, your "
82	    "implementation or your reading of the spec is wrong — investigate before "
83	    "committing.\n"
84	    "2. Re-read the specification for every convention that silently changes "
85	    "the number: which variable is regressed on which, exact seed and RNG "
86	    "call order, sample size, percentile-index convention, rounding rule, "
87	    "0- vs 1-indexing, and units. A number that is 'close' is still a failure "
88	    "if such a convention is off.\n"
89	    "3. Sanity-check magnitude and sign against the described physical/"
90	    "statistical meaning of the quantity.\n"
91	    "Only after the value survives an independent cross-check should you "
92	    "finalize the output file. If it is not a computed-number task, ignore "
93	    "this and proceed."
94	)
95	
96	
97	class NumericCrossCheckNudge(MultiHookProcessor):
98	    """Inject a one-shot numeric-reconciliation reminder on the exit-intent turn.
99	
100	    Fires at most once per task, on the first turn where the model tries to
101	    stop without a tool call (``finish_reason ∈ {end_turn, stop}`` and no
102	    ``tool_calls``) — the same signal ``CustomSelfVerifyProcessor`` keys on.
103	    The reminder is appended as a single extra user message on the next
104	    ``on_before_model`` and does not emit any tool call, so it composes with
105	    the existing self-verify keepalive rather than competing with it.
106	    """
107	
108	    _singleton_group = "numeric_crosscheck_nudge"
109	    _order = 91  # immediately after CustomSelfVerifyProcessor (90)
110	
111	    def __init__(self) -> None:
112	        self._fired = False
113	        self._pending = False
114	
115	    async def on_task_start(self, event: TaskStartEvent):
116	        self._fired = False
117	        self._pending = False
118	        yield event
119	
120	    async def on_after_model(self, event: ModelResponseEvent):
121	        exit_intent = event.finish_reason in ("end_turn", "stop") and not event.tool_calls
122	        if exit_intent and not self._fired:
123	            self._fired = True
124	            self._pending = True
125	        yield event
126	
127	    async def on_before_model(self, event: BeforeModelEvent):
128	        if not self._pending:
129	            yield event
130	            return
131	        self._pending = False
132	        msg = Message(role="user", content=_CROSSCHECK_MSG)
133	        yield dataclasses.replace(
134	            event,
135	            messages=event.messages + (msg,),
136	        )
137	
138	    async def on_task_end(self, event: TaskEndEvent):
139	        self._fired = False
140	        self._pending = False
141	        yield event
