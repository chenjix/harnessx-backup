20	### Why
21	
22	Assigned focus task_000011_d089ef35 (scientific_computing) failed after 79
23	steps / 962s in a strict A-B-A-B tool-call loop: the model kept "verifying" its
24	MSE server by re-running two Bash commands that returned byte-identical output
25	each time (`Q0: 8.25` and `Q0..Q3`), interleaved with token-limit cut-offs, for
26	~10 full cycles, and never terminated on its own. The existing
27	`LengthTruncationRecoveryProcessor` never engaged because these turns *carry
28	tool calls* (its consecutive counter resets on any tool call). The
29	`LoopDetectionProcessor` is not even in the pipeline, and its exact detector
30	only counts period-1 consecutive repeats — the alternating A-B pattern resets
31	its count to 1 every step. task_000010_644ab1c2 shows the same class:
32	fingerprint repeated 17× → budget_exceeded at 80 steps / 787s. This is a
33	genuine harness deficiency: a degenerate multi-step cycle that no current
34	mechanism terminates.
35	
36	The underlying wrong MSE values in task_000011 (Q2/Q3 computed as 38.25/55.25
37	instead of 68.25/93.25) are a model reasoning/capability gap, not a harness gap
38	— no prompt injection should hand-feed the correct extraction. Skipped as
39	capability gap; the harness fix targets only the non-termination.
40	
41	### Changes
42	
43	- `processors/cyclic_loop.py` — new `CyclicToolLoopDetector` MultiHookProcessor.
44	  Fingerprints (tool_name, tool_input, result); detects a repeating cycle of
45	  period 1..max_period at the window tail; warns at 2 identical cycles, raises
46	  `LoopDetectedError` (clean exit_reason=loop_detected) at 3.
47	- `config.yaml` — register the processor after PostCompactionRefreshProcessor.
48	
49	### Evidence
50	
51	- task_000011 result.json: steps=79, elapsed_s=962, finished=no_tool_calls,
52	  reward=0. messages.json: `uniq -c` over tool results shows exactly two
53	  distinct outputs, each 10×, in strict alternation (period-2 cycle).
54	- task_000010 result.json: steps=80, elapsed_s=787, exit=budget_exceeded.
55	  Fingerprint `ae0ed8` × 17, tail = 10+ consecutive identical calls (period-1).
56	- task_000106_23215092 (NON-target, guards against false positive): period-5
57	  cycle but outputs change across cycles (Traceback → success after scipy
58	  install); the combined call+output fingerprint differs each cycle so the
59	  detector stays silent. Verified in a standalone simulation of the detection
60	  logic: A-B×10 raises at index 5; the varying-output cycle returns `none`.
61	
62	### Uncertainty
63	
64	Whether early loop-detected termination flips reward on task_000011 is
65	unlikely (the wrong answer is a reasoning error); the primary win is reclaimed
66	budget and round-robustness. Watch for any T→F regression with
67	exit_reason=loop_detected on previously-passing tasks — that would mean the
68	cycle threshold is too tight; rollback if so.

87	### Why
88	
89	Assigned focus `task_000015_89886d8d` (software_engineering) had to OCR a
90	routing-schema PNG at `/app/routing_schema.png`, then write a `migrate.py`
91	that maps URLs to a new JSON schema. tesseract emitted
92	`Warning: Invalid resolution 0 dpi. Using 70 instead.` and OCR'd the image at
93	a degraded ~70 dpi. The extracted text was garbled (`eatalogyitem`,
94	`Ppreduet id`, `edepartment>`); the agent tried contrast/threshold/PSM tweaks
95	— none of which change the effective resolution — then gave up and *guessed*
96	the mapping. `final_pytest` accuracy 0.6793 < 0.98 threshold. The same
97	mechanism recurs on two other tasks: `task_000505_50b5162d` (SSH key OCR'd as
98	`...H9 + |J9tY +X07yG...` with space/`1`/`I`/`+`/`|` corruption) and
99	`task_002063_8c8adcfe` (`CRO-1 POLYNOMIAL: 0x9E82`, `INITIAL VALUE OXFFFE` —
100	`O`/`0` and `C`/`O` confusion on the CRC constants). All three carry the same
101	`Invalid resolution 0 dpi` warning and none ever attempted the standard
102	remediation (upscale / explicit `--dpi`) — grep across all three logs found no
103	`resize`/`--dpi`/`upscale` command. Model has the capability (tesseract + PIL
104	installed); it lacks the runtime knowledge of when to reach for it. That is a
105	Control-lever gap: fire a hint keyed on the observable low-DPI warning.
106	
107	### Changes
108	
109	- `processors/ocr_quality_guard.py` — new `OcrQualityGuardProcessor`
110	  (`MultiHookProcessor`). `on_after_tool` matches `_LOW_DPI_RE`
111	  (`invalid resolution N dpi` / `estimating resolution as N`) in the tool
112	  result and appends a one-time, task-agnostic hint: the low-DPI fallback
113	  garbles exact tokens, contrast/PSM tweaks won't help, rescale the image to
114	  ~300 dpi and re-OCR, cross-check ambiguous values, don't guess. Fires at
115	  most `max_hints` (default 1) per task; contains no task-specific constants,
116	  paths, or answers.
117	- `config.yaml` — register `OcrQualityGuardProcessor` (`_order=31`, right
118	  after `CustomEditToolProcessor`), before `CustomSelfVerifyProcessor`.
119
