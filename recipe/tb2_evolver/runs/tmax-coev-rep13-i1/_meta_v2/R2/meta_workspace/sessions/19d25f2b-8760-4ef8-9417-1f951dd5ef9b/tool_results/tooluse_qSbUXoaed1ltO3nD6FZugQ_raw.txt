20	### Why
21	
22	Baseline R0 scored 30/50 (60%). The single clearest cross-cutting failure
23	shape: 5 tasks hit `exit_reason=budget_exceeded` at the 80-step cap
24	(task_000010, task_000118, task_000264, task_001031, task_001321), spanning
25	system_administration, data_querying, data_processing and scientific_computing.
26	Reading their message tails shows the same mechanism every time — the agent
27	stalls and re-issues the *exact same* Bash command verbatim, gets the identical
28	result, narrates "I've been stuck in a loop," and then repeats the command
29	again until it burns all 80 steps. Command histograms confirm it: task_000118
30	ran one command 14×, task_001031 9×, task_001321 7×. The existing recovery
31	processors miss this: `LengthTruncationRecoveryProcessor` only fires on
32	`finish_reason=length` runaways, and `CustomEditToolProcessor` only counts
33	file-writes to the same path, so a repeated query/build/read slides past both.
34	
35	### Changes
36	
37	- `processors/repeat_command_guard.py` — new `RepeatCommandGuard`
38	  (`MultiHookProcessor`). Keys on the exact whitespace-normalised Bash command;
39	  when the same command has run >= `threshold` (3) times it appends an escalating
40	  break-out advisory to that tool's result (redirect first, hard-stop after
41	  `hard_stop_extra` more repeats). Purely additive to the tool result — never
42	  blocks execution, never mutates message history.
43	- `config.yaml` — register the guard at `_order=31` (right after
44	  `CustomEditToolProcessor`) via absolute `file://` path, `threshold: 3`,
45	  `hard_stop_extra: 2`.
46	- `system_prompt.txt` — copied byte-for-byte from R0 (SiblingSystemPromptBuilder
47	  reads it beside the YAML). Unchanged.
48	
49	### Evidence
50	
51	- `task_000264_ab8c7253`: exit_reason=budget_exceeded, 80 steps; body tail —
52	  re-issues identical `sqlite3 company.db "WITH RECURSIVE subordinates ..."`;
53	  tool returns "(exit 0, no output captured)" each time; agent narrates
54	  "I'm still getting no output captured... very strange" then repeats it.
55	- `task_001321_658ce4a8`: exit_reason=budget_exceeded, 80 steps; body tail —
56	  repeats verbatim "I've been stuck in a loop. Let me just run the pipeline..."
57	  and re-issues the same command; tool returns identical
58	  `15 /home/user/clean_codes.txt` each time (maxrepeat=7).
59	- `task_001031_a8f0eb37`: exit_reason=budget_exceeded, 80 steps; loops on the
60	  same mpi4py edit (maxrepeat=9), unchanged tool result, ignores the existing
61	  edit-limit warning.
62	- Contrast (regression guard): passing high-step tasks iterate DIVERSE commands
63	  — task_001818 (passed, 69 steps) 31 distinct commands, task_001089 (passed,
64	  80 steps) 23 distinct — so the exact-match count>=3 gate should not fire on
65	  them meaningfully.
66	
67	### Uncertainty
68	
69	The guard converts "burn 80 steps on one dead command" into "get redirected
70	with steps left"; it does not guarantee the model then solves the underlying
71	task, so flips are probabilistic, not certain. Main risk is a benign identical
72	command (service poll, watch loop) drawing an advisory — but since the message
73	is purely appended to the result and never blocks, worst case is a slightly
74	noisier tool result. Watch R2: if pass_rate doesn't improve and no predicted
75	task flips, and especially if any diverse-command passer regresses, revert.
