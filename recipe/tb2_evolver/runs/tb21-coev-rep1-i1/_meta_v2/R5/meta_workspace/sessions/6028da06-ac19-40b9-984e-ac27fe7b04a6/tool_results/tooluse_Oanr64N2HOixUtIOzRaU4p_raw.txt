20	### Why
21	
22	R0 scored 3/18 (16.7%). A per-task trace scan (`.jsonl`, biggest-string per
23	line) found a 1:1 correlation: every `exit_reason=error` task has a single
24	`raw_assistant` message whose `/message/content` is a runaway 170k–344k-char
25	string. Model `Qwen/Qwen3.5-9B` rejects inputs over ~65536 tokens with a
26	400 BadRequest; the run loop does not wrap the provider call in try/except, so
27	that 400 propagates to `exit_reason=error` and kills the task at step ~0/1 —
28	before it does any recoverable work. The stock `CompactionProcessor` can't
29	help: its token counter (`rough_token_count`, cl100k_base) undercounts this
30	model's real tokenizer, and it summarises OLD messages while leaving the single
31	oversized recent turn intact. This is a harness deficiency (a missing size-
32	bounding mechanism), not a model-knowledge gap.
33	
34	### Changes
35	
36	- `processors/context_overflow_guard.py` — new `ContextOverflowGuard`
37	  (`MultiHookProcessor`, `on_step_start`, `_order=9` right after compaction).
38	  Char-based (not token-based, since the token counter undercounts): head/tail-
39	  truncates any message whose text `content` exceeds `per_message_char_cap`,
40	  then shrinks the largest older messages until the transcript fits
41	  `total_char_budget`. Truncation is in place — message count, roles, ordering,
42	  and `tool_call_id` links preserved.
43	- `config.yaml` — register `ContextOverflowGuard` via `file://` target
44	  (`per_message_char_cap=120000`, `total_char_budget=280000`, `keep_recent=4`,
45	  `min_message_chars=2000`), positioned after `CompactionProcessor`.
46

52	- overfull-hbox: assistant content 218,307 chars, `exit=error`.
53	- configure-git-webserver: 249,882, `exit=error`.

55	- protein-assembly: 205,709, `exit=error`.
56	- sam-cell-seg: 175,527, `exit=error`.

58	- Passing tasks git-leak-recovery / headless-terminal / kv-store-grpc: max

96	### Why
97	
98	R1's context-overflow guard fully resolved the `exit_reason=error` instant-death
99	cluster — every previously-dying task now runs many steps — yet the score stayed
100	3/18. A frontmatter + episode-JSONL sweep of R1 trajectories found a new dominant
101	terminal signature: failing tasks end on a **large text-only assistant turn with
102	no tool call** (94k–254k chars). The model rambles / plans in prose instead of
103	executing Bash, and the run loop treats that as "done". The stock
104	`CustomSelfVerifyProcessor` intercepts the first such turn — but only once per
105	task — so the second ramble ends the run with the required output file never
106	written. This is a harness give-up-after-one-nudge deficiency, not a
107	domain-knowledge gap.
108	
109	### Changes
110	
111	- `processors/act_loop_keepalive.py` — new `ActLoopKeepalive` (`MultiHookProcessor`,
112	  `_order=91`, right after the stock self-verify at 90). On `on_after_model`,
113	  detects a no-tool-call stall with non-empty content and, while `max_reprompts`
114	  budget remains, injects a synthetic keepalive tool call so the loop does not
115	  `break`, and queues a short generic user nudge ("act via Bash, or emit
116	  `SUCCESS: task complete.` to finish") delivered on the next `on_before_model`.
117	  Completion-sentinel escape hatch lets a genuinely-finished agent stop. Budget
118	  exhausted → yields unchanged so the loop terminates. Keepalive tool swallowed in
119	  `on_before_tool` (`approved=False` + `synthetic_result`), mirroring the stock
120	  keepalive contract.
121	- `config.yaml` — register `ActLoopKeepalive` via `file://` after
122	  `CustomSelfVerifyProcessor` (`max_reprompts=6`, `completion_marker=SUCCESS`,
123	  `min_content_chars=1`).
124	
125	### Evidence
126	
127	- regex-log (5 steps): episode ends on a 90,105-char text-only turn (no tool
128	  call); verifier got 4 of 9 expected dates. `passed:false`.
129	- large-scale-text-editing (2 steps, `n_output_tokens:0`): ends on a 254,265-char
130	  text-only turn; `apply_macros.vim` never written → FileNotFoundError.
131	- db-wal-recovery (13 steps): ends on a 104,933-char text-only turn;
132	  `/app/recovered.json` never written.
133	- feal (149k), filter-js-from-html (125k), adaptive-rejection-sampler (97k),
134	  sam-cell-seg (175k), train-fasttext (212k), write-compressor (214k),
135	  overfull-hbox (97k), llm-inference-batching (94k): biggest assistant turn
136	  carries NO tool call (`toolInMax=False`).
137	- Passing tasks configure-git-webserver (max 1.5k), git-leak-recovery (879),
138	  kv-store-grpc (659): every biggest turn carries a tool call (`toolInMax=True`).
139	- Root cause: `harnessx/core/runloop.py` ~L745 breaks on `finish_reason in

141	  "Fires at most once per task run. On the next no-tool-call turn it stays silent."

143	### Uncertainty
144	
145	If the model rambles because it genuinely cannot solve the task (capability gap),
146	extra nudges just burn steps without flipping the task — detectable next round as
147	these tasks moving from `done` to `max_steps`/`budget_exceeded` with no filesystem
148	progress. Rollback trigger covers this. The keepalive/nudge mechanism itself is a
149	byte-for-byte reuse of the stock self-verify contract, validated by contract +
150	dry_fire + a standalone async unit exercise.

168	
169	### Why
170	
171	R1's context-overflow guard and R2's repeatable act-loop keepalive both landed
172	and are load-bearing: previously instant-dying / one-prose-stall tasks now run
173	20-100 Bash steps (R2 = 4/18, up from 3/18). A full R2 trajectory sweep found
174	the NEW dominant terminal signature is neither instant death nor a single prose
175	stall — it is that **the output file the task explicitly names is never written
176	to its exact path**. Six of the fourteen failing tasks fail the verifier's very
177	first check ("output file exists") with a `FileNotFoundError` on a `/app/<X>`
178	path that the task description told the agent to create. The agent visibly loses
179	track of the deliverable mid-run. This is a harness deficiency: the R2 keepalive
180	nudges generically ("act via Bash, verify outputs"), but the specific required
181	path is dynamic per-task context the agent stops tracking — a Control hook can
182	extract it once at task start and re-inject it at the decisive step.
183	
184	### Changes
185	
186	- `processors/output_aware_keepalive.py` — new `OutputAwareKeepalive`
187	  (`MultiHookProcessor`, `_order=91`, same slot R2 occupied). Strict superset of
188	  R2's `ActLoopKeepalive`: identical repeatable-bounded keepalive contract
189	  (synthetic keepalive tool call on a no-tool-call terminal stall; one queued
190	  user nudge on next `on_before_model`; swallow synthetic call in
191	  `on_before_tool`; SUCCESS escape hatch; budget exhausted → yield unchanged).
192	  The one addition: `on_task_start` parses `task_description` for output paths
193	  adjacent (<=40 chars) to a produce-verb (save/write/create/output/produce/
194	  store/generate/place/put/emit), and the stall nudge names those exact paths
195	  ("You have not confirmed these required output files exist yet: /app/regex.txt.
196	  Write your current best result to that exact path via Bash now, then `ls -l`").
197	  When no path extracts, the nudge is byte-for-byte R2's generic text.
198	- `config.yaml` — replace the R2 `ActLoopKeepalive` file:// target with the R3
199	  `OutputAwareKeepalive` (same kwargs: max_reprompts=6, completion_marker=SUCCESS,
200	  min_content_chars=1). One-for-one swap keeps a single stall-interceptor and
201	  preserves the +1 message-insertion contract.
202	
203	### Evidence
204	
205	- regex-log: final segment `raw_assistant` turn = 113,297 chars of prose
206	  ("Let me think about this more carefully: 1. For the date pattern: ...") with
207	  `tool_calls=0`; `/app/regex.txt` never created; task text "Save your regex in
208	  /app/regex.txt"; grep count of that path in the episode = 14 (agent knew it,
209	  never wrote it). Verifier: `assert regex_file.exists()` fails.
210	- vulnerable-secret: L50 = 45,298-char text-only turn, L51 = 184-char
211	  "previous response was cut off ... XORing with 0x42", then `exit_reason=error`;
212	  `/app/results.txt` never written (`FileNotFoundError`).
213	- large-scale-text-editing: 5 steps then `FileNotFoundError: '/app/apply_macros.vim'`;
214	  path named explicitly in task text.
215	- feal-linear-cryptanalysis: ends `done` on an 11,377-char summary of a failed
216	  brute-force; the required `/app/plaintexts.txt` is never referenced in the
217	  whole trajectory (agent drifted onto /app/pairs.txt, /app/feal.c, /app/attack.c).
218	- protein-assembly (79 steps) / sam-cell-seg (50 steps): both end without the

220	  first. (protein-assembly also hit a network wall for a PDB lookup — capability

223	  / kv-store-grpc: winning turns carry tool calls (R2 journal `toolInMax=True`),
224	  never enter the stall branch → nudge never fires.
225	
226	### Uncertainty
227	
228	If the agent rambles because it genuinely cannot solve the task (feal
229	cryptanalysis, protein PDB lookup behind blocked network), a targeted nudge
230	still produces no *correct* file — detectable next round as these tasks moving
231	to `FileNotFoundError`-cleared but content-assertion failures, or staying red
232	with no file. The three "answer-in-reasoning-but-uncommitted" tasks (regex-log,
233	large-scale-text-editing, vulnerable-secret) are the higher-confidence flips.
234	Extraction over-inclusion risk (listing an input path as an output to verify) is
235	benign — the nudge asks to confirm existence, and existing inputs pass that
236	check without being overwritten. Rollback trigger covers the capability-gap case.
