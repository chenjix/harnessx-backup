20	### Why
21	
22	Assigned focus `task_000028_7fe033ac` built a fully-correct service (nginx
23	reverse proxy → C++ backend on `/tmp/video_backend.sock` returning the ffprobe
24	frame count 150; agent verified `HTTP/1.1 200 OK` body `150`). It still scored
25	0: the external verifier's `test_final_state.py` does `import requests`, the
26	container lacks it, and pytest fails at *collection* time
27	(`ModuleNotFoundError: No module named 'requests'`). The agent can never see
28	this — verifier files are injected only after it exits. This is a harness
29	deficiency. The same root cause recurs on `task_001857` (bare
30	`/home/user/diagnostic_server &`) and `task_000297` (python http.server on
31	`127.0.0.1:8080`), all three reward 0 with `initial_pytest.passed=true`.
32	
33	The existing `HttpVerifierDepProcessor` (reminder-only) failed here two ways:
34	(1) it inspects only the Bash *command string*, so service starts whose port
35	lives in a config file (`nginx -c`) or in a bare compiled binary carry no
36	matchable token — no reminder fired on 000028/001857; (2) on 000297 a
37	reminder-style nudge was insufficient — the agent ran `python3 -c 'import
38	requests'`, saw `ModuleNotFoundError`, and finished anyway.
39	
40	### Changes
41	
42	- `processors/http_verifier_dep_install.py` — new
43	  `HttpVerifierDepInstallProcessor`. Broadens service detection (framework/port
44	  signal OR generic daemon / background-executable launch shape) and, on exit
45	  intent for a detected service task, injects ONE real `Bash` tool call:
46	  `python3 -c 'import requests' || python3 -m pip install --quiet requests`.
47	  Deterministic (does not rely on model compliance), fires at most once per task,
48	  no task-specific constants. Uses the proven `CustomSelfVerifyProcessor`
49	  synthetic-tool-call injection pattern.
50	- `config.yaml` — replaced the R0 `HttpVerifierDepProcessor` reference with the
51	  new processor (kept `_order=91`, after CustomSelfVerifyProcessor 90).
52

68	### Uncertainty
69	
70	Main risk is a false-positive service detection triggering a harmless extra pip
71	install, or the injected Bash call landing awkwardly relative to the
72	self-verify keepalive (mitigated by ordering after it and firing on a *later*
73	exit intent). If containers ever block outbound pip (offline), the install is a
74	no-op and the task stays exactly as it was — no worse than R0. Watch the R1→R2
75	gating attribution for the three predicted tasks and any T→F regressions on
76	other service tasks.
