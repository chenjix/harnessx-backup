20	### Why
21	
22	Assigned focus task_000028_7fe033ac: the agent fully solved the task — fixed
23	nginx.conf to `/tmp/video_backend.sock`, rewrote and compiled server.cpp, ran it
24	in background, wrote logrotate.conf, started nginx, and its final probe returned
25	`HTTP/1.1 200 OK ... 150` through the proxy. reward=0 anyway. The sole cause: the
26	verifier's `test_final_state.py` does `import requests`, which is not installed
27	in the container, so pytest fails at collection with
28	`ModuleNotFoundError: No module named 'requests'`. This is a structural TB2
29	gap: the verifier's test module is injected after the agent session ends and the
30	agent never sees it, so it has no way to learn the verifier needs `requests`.
31	Grep over all 21 failing tasks: exactly task_000028 and task_000958 carry this
32	`No module named 'requests'` collection failure — a small but genuine
33	network-service cluster with an identical root cause.
34	
35	### Changes
36	
37	- `processors/verifier_client_ready.py` — new `VerifierClientReadyProcessor`
38	  (MultiHookProcessor). On `on_task_start` it arms only if the task description
39	  matches a network-service regex AND a verifier regex; on the first
40	  `on_step_start` it appends one user message telling the agent that TB2 network
41	  verifiers commonly `import requests` and to make the Python HTTP client
42	  importable before finishing (idempotent, offline-friendly install snippet).
43	  Fires at most once per task.
44	- `config.yaml` — register the processor via absolute `file://` path at order 7
45	  (after env/time setup, before length/compaction control).
