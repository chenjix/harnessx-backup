18	### Why
19	
20	Assigned task `task_000118_3043e92d` (write a disk-quota monitor daemon)
21	failed with the log dir peaking at 200 MB vs the 45 MB threshold — the
22	monitor never truncated. But the graded artifact is the final script (the
23	verifier starts the monitor itself), and the agent never realised that: the
24	whole visible trajectory is a non-converging diagnostic loop. It repeatedly
25	runs `python3 monitor.py &` then `ps aux | grep`, sees defunct zombies,
26	concludes "the monitor is not showing up in the process list", and repeats
27	~15x with slightly-varied args, twice hitting the token limit, ending
28	no_tool_calls having never run the real end-to-end test or fixed the
29	script's timing bug. The same shape recurs across at least five other
30	high-step failures (`task_000958`, `task_001032`, `task_001321`,
31	`task_000015`, `task_001031`): passing tasks rarely exceed ~28 steps, while
32	these burn 57-80. Existing guards miss it — LengthTruncationRecovery only
33	fires on finish_reason=length, and LoopDetectionProcessor (not even in the
34	R0 config) keys on exact/consecutive tool-arg fingerprints, which vary here.
35	
36	### Changes
37	
38	- `processors/semantic_repetition_breaker.py` — new `SemanticRepetitionBreaker`
39	  MultiHookProcessor. `on_after_model` measures Jaccard token-overlap between
40	  the current assistant narration and recent turns; warns (injects one
41	  corrective redirect via `on_before_model`, net +1) at 3 near-dupes and
42	  raises `LoopDetectedError` at 4 (window=8, sim=0.80), so the run exits
43	  cleanly and recovers the last-good filesystem instead of exhausting budget.
44	- `config.yaml` — register the processor (file:// abs path) after
45	  LengthTruncationRecoveryProcessor and before CompactionProcessor.

66	### Uncertainty
67	
68	The raise on `task_000118` does not fire (its narration varies just enough);
69	it relies on the repeated early warn nudge redirecting the agent to verify
70	the file / fix the logic rather than re-check process state. If the model
71	ignores the nudge like it ignored the existing loop nudges, the task stays
72	failed — but budget is still reclaimed for the rest of the round. Watch for
73	any passing task flipping to exit_reason=loop_detected (false positive);
74	none appeared in offline replay.
