143	### Why
144	
145	Assigned focus `task_000010_644ab1c2` (system_administration) did NOT fail
146	on agent behavior. Its `result.json` shows `status: error`, `elapsed_s: 0.1`,
147	and NO episode/message log — the task died at host-side `docker run` before
148	the agent phase ever started. The error is a Docker container-**name
149	Conflict**: `/tmax-task000010644ab1c2-1788106887` already in use. This is
150	identical across ALL 10 `status: error` tasks this round (000010, 000028,
151	000118, 000140, 000505, 000748, 000933, 001032, 001781, 001937), each at
152	0.1s with timestamps clustered at `1788106887/…888`. Root cause:
153	`recipe/tmax_eval/docker_env.py:105` builds the container name with
154	`int(time.time())` (1-second resolution), so concurrent workers / leftover
155	containers collide. HarnessConfig only evolves the in-container processor
156	pipeline + system prompt (tb2-playbook); no hook fires before the agent
157	launches. Therefore this is neither a harness deficiency nor a model
158	capability gap — it is a runner infrastructure bug outside my writable scope.

168	  `error: "RuntimeError: docker run failed ... The container name
169	  \"/tmax-task000010644ab1c2-1788106887\" is already in use ..."`.

175	### needs_from_human

179	second-resolution time, and/or `docker rm -f <name>` before `docker run`,
180	and/or retry-with-fresh-name on Conflict. Until fixed, these 10 tasks are
181	un-scoreable regardless of agent/harness quality.
