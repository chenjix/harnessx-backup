3	"""Self-verify processor variant: verifier-runtime-deps AND stray-process hygiene.
4	
5	Motivation (harness deficiency, not task domain knowledge)
6	----------------------------------------------------------
7	TB2 verifiers run pytest against the container's *final state* after the
8	agent's session ends. Two structural facts about that verifier phase
9	repeatedly cost otherwise-correct solutions their reward, and neither is
10	visible to the agent from the task description:
11	
12	1. **Verifier runtime deps.** For network-service tasks the verifier
13	   probes the service from Python and does ``import requests`` at module
14	   import time. The agent tests with ``curl``/``wget`` and never installs
15	   ``requests``; the verifier then dies at collection with
16	   ``ModuleNotFoundError: No module named 'requests'``, scoring 0 even
17	   when the service is correct. (Closed in R1.)
18	
19	2. **Stray / zombie background processes.** Tasks that involve building
20	   or running a daemon/service push the agent to launch it repeatedly in
21	   its *persistent* Bash session during development (``./svc &``,
22	   ``nohup ... &``, ``python -m http.server &``). Each iteration can leave
23	   an orphaned or ``<defunct>`` (zombie) instance behind. Some verifiers
24	   assert *no lingering service processes* via ``pgrep -f <name>`` — and
25	   ``pgrep`` matches zombies too. The agent's dev iterations therefore
26	   fail a "clean final state" assertion even though the deliverable
27	   scripts are correct. Observed: an agent literally printed
28	   ``[vm_service] <defunct>`` in ``ps`` output, said "let me clean those
29	   up", then exited without doing so and scored 0 on
30	   ``test_no_lingering_service_processes``.
31	
32	Both are general, structural facts about how TB2 verifiers exercise
33	service/daemon tasks — not task-specific domain knowledge. Because a
34	processor cannot itself run sandbox commands, the remediation is
35	delivered as extra items in the one-shot self-verify checklist: the agent
36	is told to (a) ensure the verifier's likely Python deps are importable
37	and (b) audit for and clear any stray/zombie background processes it
38	spawned during development before exiting. A ``<defunct>`` process cannot
39	be signalled directly — it is reaped only when its parent exits — so the
40	checklist explains that the fix for zombies is to kill the *parent*
41	launcher, and that ordinary strays are killed directly.
42	
43	The class mirrors ``CustomSelfVerifyProcessor`` (same singleton group,
44	same one-shot keepalive mechanism) so it is a drop-in replacement in the
45	pipeline — only the injected checklist text differs.
46	"""
47	
48	from __future__ import annotations
49	
50	import dataclasses
51	import uuid
52	
53	from harnessx.core.events import (
54	    BeforeModelEvent,
55	    Message,
56	    ModelResponseEvent,
57	    TaskEndEvent,
58	    TaskStartEvent,
59	    ToolCall,
60	    ToolCallEvent,
61	)
62	from harnessx.core.processor import MultiHookProcessor
63	
64	_SELF_VERIFY_TOOL = "_tb2_self_verify"
65	_SELF_VERIFY_ACK = "Verification check initiated. See the message above for instructions."
66	
67	_SELF_VERIFY_MSG = """\
68	Before finishing, run through this checklist — do not skip any step even if you already verified:
69	
70	1. **Re-read the task description now.** Does your solution address every requirement, including edge cases, accuracy thresholds, and exact output format?
71	
72	2. **Check every required output file exists at its exact path:**
73	```bash
74	ls -lh /path/to/each/required/output/file
75	```
76	A script that ran without errors does NOT guarantee the file was written. Run `ls` explicitly for each required file.
77	
78	3. **Inspect the actual file contents** — `cat` or `head` each output file and confirm the values are semantically correct, not just that the file exists or is non-empty.
79	
80	4. **Validate your verification method.** Did your test actually exercise the real behavior? Tests that only check syntax, importability, or exit code 0 on a trivial case are NOT valid — they can pass even on a broken implementation.
81	
82	5. **For running services:** confirm they are still alive and reachable right now, not just that they started earlier.
83	
84	6. **If your solution runs a network service (HTTP server, socket, reverse proxy, or any endpoint that is checked over the network):** the automated checker probes such services from Python and typically does `import requests` before it can run any assertion. Confirm the Python `requests` module is importable in the same interpreter the checker will use, and install it if it is missing — a missing checker dependency fails the whole task even when your service is correct:
85	```bash
86	python3 -c "import requests" 2>/dev/null || pip install requests
87	```
88	Do this in addition to (not instead of) testing the endpoint yourself.
89	
90	7. **Clean up stray background processes you spawned while developing.** If at any point you launched a service, daemon, or long-running process in the background (`&`, `nohup`, `disown`, `python -m http.server &`, `./some_binary &`, etc.), the container's *final state* may still contain orphaned or zombie (`<defunct>`) instances from your earlier iterations. Some checkers assert that NO such process is left running (e.g. via `pgrep -f <name>`), and that check matches zombies too — so a leftover process fails the task even when your deliverable scripts are correct. List what is still running and clear anything you started:
91	```bash
92	ps -ef | grep -E '<name-of-your-service-or-binary>' | grep -v grep
93	```
94	- Kill ordinary strays directly: `pkill -f '<name>'` (or `kill <PID>`).
95	- A `<defunct>`/zombie process cannot be signalled — it is reaped only when its **parent** exits. If zombies remain, identify the parent PID (the `PPID` column in `ps -ef`) and terminate that parent so the kernel reaps the zombie.
96	- Re-run the `ps ... | grep` and confirm the list is now empty.
97	Do NOT do this if the task explicitly requires a service to stay running for the check — in that case leave exactly the one required instance alive and remove only the extra dev copies.
98	
99	Fix anything that looks wrong before exiting. When all checks pass, end your final message with:
100	**SUCCESS: task complete. Output files confirmed at [list each required path].**\
101	"""
102	
103	
104	class ServiceVerifyDepsProcessor(MultiHookProcessor):
105	    """One-shot self-verify prompt (files + services + verifier deps + process hygiene).
106	
107	    Drop-in replacement for ``CustomSelfVerifyProcessor``: fires at most
108	    once per task run, on the first no-tool-call exit intent, injecting a
109	    single extra user message and a synthetic keepalive tool call so the
110	    loop continues one more turn.
111	    """
112	
113	    _singleton_group = "tb2_self_verify"
114	    _order = 90
115	
116	    def __init__(self) -> None:
117	        self._verified = False
118	        self._pending_message: str = ""
119	
120	    async def on_task_start(self, event: TaskStartEvent):
121	        self._verified = False
122	        self._pending_message = ""
123	        yield event
124	
125	    async def on_before_model(self, event: BeforeModelEvent):
126	        if not self._pending_message:
127	            yield event
128	            return
129	        msg = self._pending_message
130	        self._pending_message = ""
131	        yield dataclasses.replace(
132	            event,
133	            messages=event.messages + (Message(role="user", content=msg),),
134	        )
135	
136	    async def on_after_model(self, event: ModelResponseEvent):
137	        exit_intent = event.finish_reason in ("end_turn", "stop") and not event.tool_calls
138	        if exit_intent and not self._verified:
139	            self._verified = True
140	            self._pending_message = _SELF_VERIFY_MSG
141	            keepalive = ToolCall(
142	                id=f"sv-{uuid.uuid4().hex[:8]}",
143	                name=_SELF_VERIFY_TOOL,
144	                input={},
145	            )
146	            yield dataclasses.replace(event, tool_calls=(keepalive,))
147	        else:
148	            yield event
149	
150	    async def on_before_tool(self, event: ToolCallEvent):
151	        if event.tool_name == _SELF_VERIFY_TOOL:
152	            yield dataclasses.replace(event, approved=False, synthetic_result=_SELF_VERIFY_ACK)
153	        else:
154	            yield event
155	
156	    async def on_task_end(self, event: TaskEndEvent):
157	        self._verified = False
158	        self._pending_message = ""
159	        yield event
